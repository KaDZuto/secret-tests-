# Шина проверки русского текста (qa_lang)

Это шина между агентами проекта LivingVN, которая проверяет **смысл, связность и грамотность**
написанного по-русски сюжета. Работу делает агент-контролёр: небольшая модель, которая хорошо
знает русский язык, но не сильна в длинном контексте.

## Главный принцип

Всё, что можно проверить скриптом, проверяет скрипт. Модели достаётся только то, что скрипт
не умеет: отвечает ли реплика на вопрос, следует ли строка из предыдущей, правда ли, что
персонаж знает то, о чём говорит.

| слой | кто проверяет | что именно | стоимость |
|---|---|---|---|
| механика и движок | `tools/ru_qa.py` | поля, ссылки, флаги, типы шагов, формат для движка | 0 токенов, всегда одинаково |
| орфография и пунктуация | `tools/ru_text.py` | кавычки, тире, многоточия, латиница в русском слове, «е/ё», сленг, заглушки, повторы | 0 токенов, всегда одинаково |
| смысл и связность | агент-контролёр | 5 вопросов к каждой строке, ответ ok / bad / unsure | только нужные строки |

## Где лежит сюжет

| файл | что это | строк |
|---|---|---|
| `data/story_sao.json` | «Осколки Айнкрада», 7 сцен, написанный сюжет агента | 124 |
| `game/story_chapter.py` | первая глава, написанная руками, 24 части с ветками | 381 |
| `game/local_story.py` | запасные реплики офлайн-режима | 32 |
| `game/data/story_example.json` | демо-мир, текст английский | — |
| `game/demo.rpy`, `game/story_chapter.rpy` | короткие вставки | 8 |

Проверяются первые три. Полный список с числом строк:

```bash
python3 tools/ru_qa.py list data/story_sao.json,game/story_chapter.py,game/local_story.py
```

## Цикл работы

Человек один раз готовит сюжет к проверке:

```bash
python3 tools/ru_qa_bus.py scan data/story_sao.json --tag sao
```

Дальше агент-контролёр идёт по кругу, пока не ответит на все пакеты:

```bash
python3 tools/ru_qa_bus.py status sao     # сколько осталось
python3 tools/ru_qa_bus.py next sao        # показать следующий пакет (текст + бланк)
python3 tools/ru_qa_bus.py verdict sao sao-01 --file /tmp/ответ.json
python3 tools/ru_qa_bus.py finish sao      # собрать отчёт
```

Каждая команда сама печатает, что делать дальше. Ответ не принимается, если в нём нет
каждой строки пакета или стоит значение не из `ok | bad | unsure`, — команда `verdict`
скажет, что исправить.

## Файлы шины

| путь | что это |
|---|---|
| `packets/<tag>/<id>.txt` | что читать: строка, её соседи, кто говорит, что уже нашёл скрипт |
| `packets/<tag>/<id>.json` | бланк ответа: все id уже проставлены, поля ждут значения |
| `verdicts/<id>.json` | ответ агента (тот же бланк, заполненный) |
| `report.md` | итоговый отчёт для человека |
| `report.json` | тот же отчёт в виде данных |
| `tasks.json` | состояние: какие сюжеты готовы, какие пакеты закрыты (создаётся скриптом) |
| `fix/<tag>.json` | бланк правок: адрес, текст, находка, пустые `new` / `split` / `skip` |
| `inbox.jsonl` | заявки на проверку и на правку |
| `outbox.jsonl` | ответы шины |

## Режим правки

Обнаружение и правка разделены. Сначала скрипт собирает бланк, модель заполняет только поля
`new` / `split` / `skip`, и гвард проверяет результат до записи.

```bash
python3 tools/ru_patch.py template game/story_chapter.py --out /tmp/правки.json --limit 30
# модель заполняет бланк и сдаёт на проверку, ничего не записывая
python3 tools/ru_patch.py check game/story_chapter.py /tmp/правки.json
# применение: пишет .fixed-копию и сверяет всё, что запрещено менять
python3 tools/ru_patch.py apply game/story_chapter.py /tmp/правки.json --out /tmp/ch1.fixed.py
```

Системная инструкция для модели: `agent_bus/qa_lang/SYSTEM.md`.

Что гвард отказывает автоматически: неизвестный адрес строки (с подсказкой похожего), `new` и
`split` вместе, две правки одной строки, обрыв строки до 70 % от исходника, `new` в виде куска
JSON, незакрытые кавычки, битый JSON (с номером строки и позицией). Что гвард проверяет в
записанном файле: набор говорящих, фонов, эмоций, `goto`, флагов и id вариантов, число шагов,
общий объём текста, разбираемость файла. Любое расхождение — запись отменяется.

## Порядок работы человека

1. Прочитал отчёт `agent_bus/qa_lang/report.md`.
2. Ошибки движка (`engine.*`) чинит в первую очередь: текст не покажется вообще.
3. Ошибки текста (`typo.*`, `style.*`) — одной правкой по коду, скрипт уже показал все места.
4. Вердикты агента («смысл», «связность») — глазами, по одной строке.
5. После правок: `scan` заново и проверить, что число находок упало.
