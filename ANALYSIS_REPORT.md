### Конвейер генерации сюжета

```
Игрок создаёт игру
  → create_game_from_creator() [engine.py:380]
    → story_world_request() → модель генерирует мир
    → initialize_game(world)
      → Режим: "ai" (если настроен) или "chapter" (рукописная глава)

Игрок кликает "Далее"
  → next_step() [engine.py:712]
    → ensure_buffer(2) [engine.py:681]
      → AI режим: _story_request() [engine.py:580]
        → story_pipeline.start_job() → worker-поток
          → prompts_story.story_request() → промпт
          → ai_client.call_chat() → HTTP POST
          → parse_steps() → normalize_all()
          → Если включён супервизор: _review() → вторая модель оценивает
        → _wait_for_story_screen() → Ren'Py screen с таймером
      → Chapter режим: _extend_chapter() → story_chapter.next_steps()
    → apply_visuals(step) → фоны, персонажи, музыка
    → consume_dialogue(step) → текст, состояние, история
    → Если есть choices: apply_choice() → выбор игрока
```

## 2. Критические баги

### 2.1. `config.gamedir` вместо `store.config.gamedir`

**Файл:** `game/engine.py:1273`
**Проблема:** Используется голый `config` вместо `store.config`. Вызовет `NameError` при загрузке истории из буфера обмена.

### 2.2. Состояние гонки на `_PENDING_VOICE`

**Файл:** `game/engine.py:1109`
**Проблема:** Модульный словарь `_PENDING_VOICE` используется из worker-потока TTS (запись) и из основного потока-таймера (чтение и очистка). Без блокировки возможна потеря аудио или воспроизведение устаревших данных.

### 2.3. Отладочный файл `zz_ogurec.rpy` в проекте

**Файл:** `game/zz_ogurec.rpy`
**Проблема:** Файл отладки оставлен в проекте. При запуске с аргументом `+zz_ogurec` вызывает `renpy.get_renderer_info`, которого нет в Ren'Py 8.3.7 — краш. Файл должен быть удалён.
**Доказательство:** `traceback.txt` показывает именно эту ошибку.

### 2.4. Ошибка стиля `border` в `vn_styles.rpy`

**Файл:** `game/vn_styles.rpy:241`
**Проблема:** `style property border is not known` — свойство `border` удалено в Ren'Py 8. Нужно заменить на `Frame` с 9-slice или убрать.
**Доказательство:** `errors.txt`

### 2.5. Баг с описанием при создании новой игры

**Файл:** `game/screens.rpy:1566` + `game/engine.py:380-428`
**Проблема:** Пользователь сообщает, что при создании новой игры можно изменить только название, но не описание.

**Анализ:**
- Поле `creator_description` существует в коде экрана и использует `VariableInputValue`
- `create_game_from_creator()` передаёт `description` в `brief`
- Но при fallback на `bootstrap_world()` → `random_world()` описание теряется
- Ren'Py `input` — только однострочный, неудобно для длинного описания
- Нет валидации, что описание реально используется при создании мира

**Нужно исправить:**
1. Сделать поле описания многострочным (использовать `viewport` + `input` или `renpy.input()`)
2. Добавить валидацию: если описание задано, оно должно попасть в мир
3. Показать описание в мире после создания (проверить, что оно не потерялось)
4. Добавить подсказку о том, что описание влияет на генерацию

### 2.6. Нельзя играть длинную главу по SAO

**Файл:** `game/story_chapter.py` + `game/story_chapter.rpy`
**Проблема:** Единственная рукописная глава — «Глава первая. Лагерь, который ждал» (летний лагерь). Главы по SAO нет. Файл `data/story_sao.json` существует (7 сцен, 10 персонажей, 8 локаций), но нет загрузчика для него.

**Что нужно:**
1. Создать формат файла главы (JSON или скрипт)
2. Написать загрузчик внешних глав
3. Добавить в интерфейс выбор главы
4. Написать полноценную SAO-главу (или конвертировать `story_sao.json`)

## 7. Генератор картинок — оценка

### Что есть

Инструменты в `tools/`:
- `import_sprite_pack.py` — импорт готовых спрайтов
- `import_layered_pack.py` — импорт слоёных спрайтов с измерением смещений
- `bake_es_layered.py` — запекание спрайтов Everlasting Summer
- `bake_ddlc.py` — запекание спрайтов DDLC
- `measure_face_strips.py` — измерение геометрии полос лица
- `measure_face_offsets.py` — измерение смещений лица на теле
- `apply_face_naming.py` — слияние геометрии с разметкой

### Оценка

**Инструменты хорошо спроектированы для своей задачи.** Они предназначены для одноразового импорта существующих игровых ассетов, а не для генерации в рантайме. Система слоёных спрайтов (запекание при импорте, отрисовка при рендере) — правильная архитектура.

**Зависимость от ImageMagick** — не Python-библиотека, должна быть установлена отдельно. Это задокументировано, но требует внимания.

**Алгоритм измерения смещений** (`find_offset` в `import_layered_pack.py`) — самая интересная часть. Использует маску выражения и поиск по пикселям. Работает корректно, но медленно (~2.5 мин на персонажа).

### Рекомендация

**Оставить инструменты.** Они нужны для запекания оставшихся 8 персонажей SAO. Но:
1. Задокументировать зависимость от ImageMagick в README
2. Добавить индикатор прогресса в `measure_face_offsets.py`
3. После запекания всех персонажей инструменты можно убрать из основной ветки

## 10. Заключение

Проект представляет собой рабочий MVP визуальной новеллы с AI-генерацией сюжета. Архитектура в целом правильная: микро-пакеты, супервизор, рукописная глава как fallback, система готовых наборов ассетов.

Основные проблемы:
- Критические баги (отладочный файл, гонка, баг с описанием)
- Незавершённая работа (8 персонажей SAO, загрузчик глав, адаптивный UI)
- Отсутствие проверки качества текста
- Отсутствие настроек персонажей по отдельности

При правильной доработке проект может стать полноценной визуальной новеллой с бесконечной генерацией сюжета.
